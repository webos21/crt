
# 프로젝트 중간 정리 계획 

## 1. CRT 목표 구체화

CRT는 Linux Kernel 기반의 Embedded Device를 개발하기 위한 
Cross-platform C Runtime이다.

예상 가능한 사용 대상은 Settop-box나 Raspberry Pi를 활용한 Game Console,
Industrial HMI(Human-Machine Interface / ex: PowerView 780),
차량용 IVI(In-Vehicle Infortainment system) 등이다.

이러한 장치들을 개발하다 보면, Application 들이 개발자의 Host OS(Linux/Windows/MacOS)에서
동일한 소스 기반으로 실제 구동 및 디버깅이 가능할 때, 그 생산성을 크게 향상시킬 수 있다.

더불어, 3개 OS를 대상으로 Application을 출시하고자 하는 곳이 있다면,
이 경우에도 CRT를 활용하여 하나의 소스 코드로 3개 OS용
Native Binary Executables을 만들어 낼 수 있다.


## 2. CRT 활용 단계 구분

CRT 프로젝트의 방향성이 Source Code 컴파일 기반의 호환성 확보와 동시에
Linux/Windows/MacOS 각 OS에서의 Native Binary Executables을 만들어 내는 것이기에
linker는 폴더만 유지하고 그 구현은 Roadmap에서는 일단 제외하고, 이 내용을 문서에 기록한다.

CRT가 계속 확장되고 있는데, 사용 목적별로 필요한 수준이 다르다.
이를 적절히 지원하기 위해, CRT 활용 단계를 다음과 같이 나누고자 한다.


### 2-1. C 만 활용 : libc/libm/libdl/shell

* C Compiler와 Runtime 만을 활용하고 싶은 경우
* C 기반 Library만 Porting 및 사용 : zlib, libpng, libffi, mbedtls, curl 등


### 2-2. C++ 까지 활용 : libstdc++

* C/C++ Compiler와 Runtime까지 활용하고 싶은 경우
* 좀더 많은 C/C++ 기반 Library 활용 가능


### 2-3. SImple Graphics 단계

* 단순히 하나의 Window와 그리기 도구만 활용
* Keyboard/Mouse Input 까지는 필요

ex) Industrial HMI 등에 활용


### 4. Graphics/Media 단계

* Skia 및 Vulkan/D3D12/Metal 등 HW(GPU) Acceleration까지 활용
* FFmpeg 등 Media Library를 활용한 영상 재생까지 가능

ex) Settop-box


### 5. JS 단계

* Javascript를 활용한 편리한 Application 제작까지 가능



## 3. 빌드 구조 정리

앞서 정리된 CRT 활용 단계에 따라, 필요한 부분만 Build해서
사용하고 검증할 수 있도록 정리 필요.

`cmake --workflow --preset <preset>`와
`cmake --build --preset <preset> --target <target>` 기반으로 계획.


* workflow 는 C 활용 단계까지만 가는 것으로 정리
  - make, mksh, toybox는 포함
  - ctest도 C 활용 단계까지만으로 분리

* poring은 현재 구조 유지
  - 개별 빌드도 가능하고, 각 단계에 필요한 것들은 의존성에 의해 자동 포함되는 구조

* libstdc++
  - crt-libcxx-build : 빌드 진행
  - crt-libcxx-test : 테스트 진행

* libcrtgfx
  - crt-gfx-build : 빌드 진행 / Demo도 함께 빌드
  - crt-gfx-test : 테스트 진행

* libcrtmedia
  - crt-media-build : 빌드 진행 / Demo도 함께 빌드
  - crt-media-test : 테스트 진행

* libcrtjs
  - crt-js-build : 빌드 진행 / Demo도 함께 빌드
  - crt-js-test : 테스트 진행



## 4. 빌드 툴 배포 구조

CRT SDK compiler driver 정리: 현재 crt-cc/crt-c++의 공통 옵션을 relocatable Clang .cfg 파일로 이동하고, 
링크 모드 및 startup/runtime 선택만 담당하는 얇은 launcher를 제공한다. 

사용자는 CC=crt-clang, CXX=crt-clang++만 지정하면 CRT sysroot와 기본 ABI 정책을 적용받는다.

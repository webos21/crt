
# webos21/crt 마켓 포지셔닝 및 생태계 확장 전략 보고서

## 1. 프로젝트 현재 상태 및 베이스라인 (Current Baseline)
webos21/crt (Cross-platform C Runtime)는 Android Bionic libc를 베이스라인으로 삼아 호스트 OS의 제약을 뛰어넘는 초경량 OS 추상화 레이어(OSA) 및 플랫폼 적응 레이어(PAL) 구축을 지향합니다.

* 검증된 네이티브 스택: 의존성이 매우 까다롭고 무거운 오픈소스인 FFmpeg, SQLite, Curl, mbedTLS의 빌드 레시피를 확보하고 실제 동작 검증 완료.
* 그래픽 서브시스템: Skia CPU-raster 마일스톤 달성. 호스트 GPU 드라이버 의존성 없이 순수 C++ 연산만으로 독립적인 픽셀 버퍼 제어 성공.
* 최종 아키텍처 목표: 자체 동적 링커/로더(Dynamic Linker/Loader)를 내장하여 가상화(VM) 없이 호스트 OS와 완전히 격리된 독립 실행 영토 구축.

------------------------------
## 2. 핵심 기술적 갈등과 아키텍처적 돌파구 (Dilemma & Solution)
프로젝트가 추구하는 "자체 링커를 통한 완벽한 격리"라는 이상과, 고성능 화면 출력을 위해 호스트 OS의 독점 API(macOS Metal, Windows DirectX 12)를 호출해야 하는 현실이 정면으로 충돌합니다.
## 위험 요인 (Risks)

* 컨텍스트 충돌: 자체 ELF 주소 맵핑 공간에 호스트 OS의 시스템 드라이버 DLL이 불쑥 로드되면 스레드 로컬 스토리지(TLS) 및 메모리 정렬 오염 발생.
* 예외 처리 메커니즘 불일치: Windows 환경에서 DWARF 규격(libunwind)을 강제할 경우, DX12 드라이버가 던지는 네이티브 Windows SEH 예외를 캐치하지 못해 프로세스가 즉시 크래시됨.

## 생존 아키텍처 (Chromium Ozone + Skia 분리 구조)

* Ozone 구조 벤치마킹: 창 관리(Windowing)와 호스트 GPU 가속 컨텍스트를 메인 런타임과 완전히 분리된 독립된 샌드박스 스레드(Worker Thread)로 격리.
* Skia 백엔드 분리 수용: 애플리케이션 핵심 로직과 UI 드로잉은 CRT 자체 영역 안에서 순수하게 처리하고, 최종 화면 프리젠테이션만 격리된 호스트 래퍼 영역에 위임하여 드라이버 오염을 원천 차단.

## 3. 새로운 위협: AI 코딩 에이전트의 침공과 방어 전략
Cursor, Copilot, Cline 등 LLM 기반 AI 개발 도구의 급격한 발전으로, 수만 줄의 레거시 C/C++ 코드를 모던 언어인 Rust(Tauri)나 Dart(Flutter)로 변환하는 비용이 90% 이상 절감되었습니다. 단순히 "C/C++ 소스 코드를 그대로 데스크톱 앱으로 컴파일해 준다"는 과거의 논리로는 일반 개발자 시장에서 살아남을 수 없습니다.
## AI가 절대로 침범할 수 없는 webos21/crt만의 3대 방어막 (AI Blindspots)

   1. 규제 및 인증의 벽 (The Certification Wall): 의료기기(HMI), 국방, 항공, 자동차 분야의 C/C++ 코드는 수억~수십억 원의 비용과 수개 년의 시간을 들여 안전 규격 인증(ISO 26262, DO-178C, FDA 등)을 받은 자산입니다. AI로 코드를 한 줄이라도 바꾸는 순간 기존 인증은 전면 무효화됩니다. 코드를 단 한 글자도 건드리지 않고 환경만 격리해 주는 CRT가 유일한 정답입니다.
   2. 소스 없는 블랙박스 바이너리 (Black-Box Binaries): 산업계 레거시 시스템에는 제조사가 소스를 분실했거나, 타사 제휴로 인해 소스 없이 오직 정적/동적 라이브러리(.a, .so) 형태로만 존재하는 코드가 수없이 많습니다. AI는 소스가 없는 바이너리를 번역할 수 없습니다. Bionic 기반의 ABI 호환성을 제공하는 CRT만이 이 자산들을 Windows/macOS로 끌고 올 수 있습니다.
   3. 결과론적 결정성 시뮬레이션 (Deterministic Simulation): AI가 구문(Syntax)은 Rust로 예쁘게 바꿔줄 수 있지만, 하드웨어 저수준의 타이밍, 메모리 풋프린트, 파일 시스템 I/O 병목까지 똑같이 재현해 주지는 못합니다. CRT는 가상화 오헤베드 없이 네이티브 바이너리 레벨에서 완벽한 데스크톱 시뮬레이터 역할을 수행합니다.

## 4. 전략적 마켓 포지셔닝: 일반 앱 시장에서 산업계 틈새시장으로
Electron, Tauri, Flutter와 일반 소비자용(B2C) 데스크톱 앱 시장에서 정면 대결하는 것은 자살행위입니다. webos21/crt는 "극도로 보수적이며 고성능과 규제 준수가 필수적인 산업 및 가상화 시장"을 정밀 타격해야 합니다.

[패배하는 포지셔닝] ➡️ "Electron을 대체하기 위해 C/C++로 데스크톱 앱을 만드는 프레임워크"
[승리하는 포지셔닝] ➡️ "미션 크리티컬 임베디드 시스템 및 인증된 C/C++ 자산을 위한 
                     비용 절감형 초고속 데스크톱 시뮬레이터 겸 마이그레이션 툴킷"

## 핵심 타겟 고객층 (Target Audience)

* 임베디드 하드웨어 및 HMI 제조업체: (셋톱박스, 의료용 디스플레이, 키오스크 등) 타겟 보드에 매번 이미지를 굽거나 무거운 QEMU 가상머신을 띄울 필요 없이, Windows 11/macOS PC 개발 환경에서 0.1초 만에 네이티브 창으로 UI와 로직을 검증하는 초고속 개발 환경 제공.
* Android NDK 자산 보존 기업: 고성능 C++ 안드로이드 엔진을 보유하고 있으나, 복잡한 MSVC/Xcode 툴체인 파편화 때문에 PC/데스크톱 버전 출시를 포기했던 기업들의 전환 도구.
